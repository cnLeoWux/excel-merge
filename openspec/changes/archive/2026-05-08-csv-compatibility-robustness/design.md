## Context

The Excel Merge application relies on pandas `read_csv` and `read_excel` to ingest order and payment data. Third-party payment files (e.g., Alipay, WeChat) often contain edge cases like scientific notation avoidance string prefixes (`="2025..."`, `\t2025...`) and trailing spaces. These edge cases result in either precision loss for 20+ digit order numbers or matching failures. Furthermore, malformed CSV rows caused entire datasets to fail or drop rows silently.

## Goals / Non-Goals

**Goals:**
- Guarantee complete accuracy of long numerical strings representing order numbers during CSV read phases.
- Clean dirty CSV prefix/suffix artifacts generated by domestic payment gateways to ensure robust matching operations.
- Warn, rather than silently fail/skip, on malformed CSV lines.
- Remove arbitrarily strict column count limits on successful DataFrame loads.

**Non-Goals:**
- Completely rewrite the matching engine.
- Introduce new external dependencies for data wrangling.
- Add database-level data sanitization (all sanitization remains in-memory via pandas).

## Decisions

1. **Use `dtype=str` for all CSV ingestion**
   - *Rationale*: We must prevent pandas from inferring large numbers as `float64`, which destroys 20+ digit exact precision (truncating trailing digits). String ingestion preserves exactly what the file contains.
2. **Post-process cleanup via `.str.strip('="\t ')`**
   - *Rationale*: Many payment CSVs wrap order numbers in `=”1234”` or prepend tabs. Running a vectorised `.strip()` across string columns cleans up both visual spacing and protective delimiters efficiently without affecting valid data formats.
3. **Change `on_bad_lines="skip"` to `"warn"`**
   - *Rationale*: A malformed line should trigger a standard warning (in `stderr` or logs) instead of silently disappearing. This aids in auditing missing orders.
4. **Relax shape check to `>= 2` columns**
   - *Rationale*: Some user-defined minimal datasets may only have `订单号` and `订单金额`. The previous requirement of `> 5` columns arbitrarily rejected valid sparse datasets.

## Risks / Trade-offs

- **Risk: Memory / processing overhead from string matching.**
  *Mitigation*: We are already treating `订单号` as strings downstream. Coercing earlier to string slightly increases parsing time but drastically increases correctness, which is our core priority.
- **Risk: Warnings spamming the console.**
  *Mitigation*: The `on_bad_lines="warn"` parameter uses python's standard warnings mechanism, which won't block the actual program flow but will inform the operator.
